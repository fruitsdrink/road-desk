# 自研远控换芯探针：避坑清单

Status: active（随探针修订）  
Related: [spike-media-replace.md](./spike-media-replace.md), [ADR-0004](./adr/0004-compliant-media-self-developed.md), [前序 RESULTS](../spikes/media-plane/RESULTS.md)

目的：汇总自研远控（含网络）常见坑，以及本仓库**已经踩过/已预判**的坑；每条都落到 **本探针必须怎么避**。  
用法：阶段出门与每周进度检查时过一遍「探针对策」列；RESULTS 进度日志可写「本周避坑抽查」。

图例：**历史** = 本产品曾踩；**已知** = 前序探针/主线已观察到；**行业** = 远控通用风险。

## B. 采集与编码

| # | 坑 | 类型 | 为何危险 | 本探针怎么避 |
|---|----|------|----------|--------------|
| B1 | GDI 采不全帧却当「脏区协议」发 | 行业 | 带宽与 CPU 双爆，拖窗必卡 | 真脏矩形；无变化可跳过或极小心跳 |

| B5 | 粉紫拖影当「自己的 bug」死磕 | 已知 | GDI+色键/overlay 固有；经典 VNC 也有 | 记现象；**不**据此判失败、不为此上 Mirror |

| B8 | 编码器开 B 帧 / lookahead / 深队列 | 行业 | 人为加延迟 | P0 无视频硬编；若以后上软编也保持低延迟预设 |

## E. 网络与传输（本探针重点补强）

> MVP/探针场景是**路段内网直连**，不测公网打洞与中继；但 TCP/TLS/mux 坑在内网一样会踩。

| # | 坑 | 类型 | 为何危险 | 本探针怎么避 |
|---|----|------|----------|--------------|
| E1 | **Nagle + 延迟 ACK** 叠加 | 行业 | 小包 Input 被合成，键鼠多 40～200ms 级迟滞 | TLS/TCP 上对套接字设 `TCP_NODELAY`；Input 路径禁止为「省包」再攒批过大 |
| E2 | 单连接上**无优先级 mux**（先到先得写满 Video） | 行业 | 与 C3 同构：键鼠饿死 | 应用层调度：有 Input/Control 待发时先写它们；Video 可打断/让路 |
| E3 | 把「多 TCP」当 P0 | 行业 | 防火墙/双连接状态机复杂，收益未证 | P0 单 TLS；**仅当** G3 仍 Input 饿死再评估第二连接 |
| E4 | 忽略 **send/recv 缓冲与部分写** | 行业 | 大帧写一半当写完 → 协议错乱、花屏、断开 | 带偏移的写循环；读侧长度帧定界（`channel + len + payload`） |
| E5 | 长度字段无上限 / 不校验 | 行业 | 内存爆炸、畸形包 | `payload_len` 硬上限（按最大桌面与编码估，超限断连并打日志） |
| E6 | 消息边界与 TLS 记录混淆 | 行业 | 以为一次 `Read` 就是一帧 | 应用层自己拼帧；TLS 只当字节流 |
| E7 | 阻塞 `send` 卡住唯一网络线程 | 行业 | 心跳与 Input 全停 | 发送线程可堵在 Video；Input 入队；或非阻塞 + 状态机（选一种写清） |
| E8 | 心跳缺失 → 半开连接挂尸 | 行业 | 一端以为在线，互斥不释放 | Control 心跳 + 读超时；断连路径必 `SessionMutex` release |
| E9 | 重连风暴 / 不退避 | 行业 | 打满 Host、日志炸 | Viewer 重连指数退避；Host 拒绝要有原因码 |
| E10 | 只测 localhost / 同机 | 行业 | 看不到带宽与 RTT 真实形态 | G2+ 至少跨机内网；G4 同车道环境 |
| E11 | 用 **UDP 无可靠层** 传桌面当 P0 | 行业 | 花屏/撕裂自研成本高 | P0 **TCP+TLS**；不引入自研 FEC |
| E12 | 公网/NAT/中继假设混进探针 | 产品范围 | 扩 scope | 文档写明仅直连；中继是目标能力，本探针不做 |
| E13 | 防火墙仅放行「偶然端口」、无说明 | 行业 | 现场连不上误判代码坏 | 文档固定默认端口；失败日志区分 bind/connect/TLS/auth |
| E14 | 大帧 > 通路有效载荷却当原子 | 行业 | 中间设备少见，内网交换机一般 OK；更常见是应用层一次分配失败 | 分片是 TCP 的事；应用层按 len 流式读，避免「整帧进单次栈数组」 |
| E15 | 带宽估满发、无降级 | 行业 | 拖窗时吞吐打满 → 延迟升 | 积压时降帧/升合并，而不是提高采集率硬撑 |
| E16 | IPv6/双栈、代理环境未声明 | 行业 | 联调「连错地址」 | P0 文档写死：IPv4 直连；不走系统 HTTP 代理 |

### E 附：本探针网络验收最小集

- [ ] `TCP_NODELAY` 已开（Host/Viewer 两侧）
- [ ] 人为限速或塞大 Video 时，点击仍可在可感知时间内生效（G3）
- [ ] 拔网线 / 杀 Viewer 后，Host 互斥与监听恢复可再连（E8）
- [ ] 超长 `payload_len` 被拒绝且进程不崩（E5）
- [ ] 日志能区分：TCP 失败 / TLS 失败 / 鉴权失败 / 互斥拒绝（E13）

## L. DPI / 缩放（Win8+ 必避）

> Host 主战场仍是 Win7，但 **Viewer 常在 Win10/11**，部分机电机/服务器也可能是 Win8+。  
> Win8.1 起 **每监视器 DPI**、Win10 起缩放更常见——远控里「画面像素」和「鼠标坐标」一旦混用逻辑/物理像素，必现点偏。  
> 前序 `spike_viewer` 曾注释「Intentional DPI-unaware」——**换芯探针不再沿用该省事策略**。

### L.0 协议约定（钉死）

| 项 | 约定 |
|----|------|
| 画面尺寸 / 脏矩形 / 指针坐标 | 一律为 Host **帧缓冲像素**（与 GDI `BitBlt` 缓冲宽高一致的物理桌面像素） |
| Viewer 窗口缩放 | 仅做「远端像素 ↔ 客户区」的 letterbox/等比映射；**不得**再叠一层未声明的 OS 虚拟化坐标 |
| 多监视器不同 DPI | MVP/探针仍只传**主屏**；不在 P0 做跨屏 DPI 拼接 |

### L.1 坑与对策

| # | 坑 | 类型 | 为何危险 | 本探针怎么避 |
|---|----|------|----------|--------------|
| L1 | 进程 **DPI 未感知**（尤其 Viewer 在 125%/150%） | 行业 | Win8+ 对窗/坐标虚拟化：客户区逻辑像素 ≠ 真像素；鼠标映射漂；窗口发糊 | Host：启动早期 `SetProcessDPIAware`（Win7）或等价 system-DPI aware。**Viewer（Win8+）**：清单或 API 声明至少 **System DPI Aware**；禁止「为省事故意 unaware」 |
| L2 | Host 与 Viewer **感知级别不一致**且代码假设一致 | 行业 | 一端按物理、一端按逻辑 → 点击系统性偏移 | 两端都 aware；协议只认 Host 帧像素；Viewer 映射只用自己客户区真像素尺寸（`GetClientRect` + 必要时物理化） |
| L3 | 用 `GetSystemMetrics(SM_CXxSCREEN)` 在 **Per-Monitor 未感知** 进程里当「缓冲宽高」 | 行业 | 返回值可能是虚拟化后的；与 BitBlt 实际像素不一致 | Host 在 DPI aware 后取屏；Control 下发的 `width/height` **必须等于** 实际帧缓冲；注入侧用同一对 w/h 做 `SendInput` 绝对坐标换算 |
| L4 | 声明了 **Per-Monitor V2** 却仍按「单系统 DPI + 主屏 metrics」写死 | 行业 | 副屏/跨窗 DPI 变化时错位；`WM_DPICHANGED` 后旧比例 | 探针 P0：**不要**上 Per-Monitor V2，除非同时处理 `WM_DPICHANGED` 与客户区重算。优先 **System DPI Aware** + 主屏 |
| L5 | Viewer letterbox 只按 `GetClientRect` 逻辑像素，忽略 DPI | 行业 | 高分屏上点偏一截 | DPI aware 后 `GetClientRect` 即为该窗客户区像素；映射：`remote = (client - letterbox_origin) / scale`；缩放与原点变化要在 `WM_SIZE`/`WM_DPICHANGED` 重算 |
| L6 | 忽略 **`WM_DPICHANGED`**（用户改缩放或窗拖到另一 DPI 屏） | 行业 | 改缩放后旧变换矩阵仍用 → 突然点不准 | Viewer 处理 `WM_DPICHANGED`（或至少 `WM_DPICHANGED` 后 Invalidate + 重算 letterbox）；不要求热切换完美动画，但**坐标必须立刻正确** |
| L7 | 混用「逻辑坐标 API」与「物理帧」 | 行业 | 例如未感知时的屏幕坐标、或部分 `PhysicalToLogicalPoint` 误用 | 注入路径：Viewer 客户区像素 → 远端帧像素（整数）→ Host `SendInput` 绝对坐标按 **帧 w/h** 映射到 0..65535；禁止在中途再乘/除一次「缩放比例百分比」 |
| L8 | 只测 100% 缩放 | 已知风险 | 开发机 100%、现场 125%/150% 才爆 | **验收矩阵**见 L.2；未测高 DPI 不得标 G3 完成 |
| L9 | 字体/控件按 DPI 拉大导致 Viewer UI 挡画面，误改帧缩放 | 行业 | 把工具条尺寸算进远端映射 | 远端画面区与工具条分窗或固定排除；letterbox **只**对画面 HWND 客户区 |
| L10 | Host Win8+ 未 aware，BitBlt「看起来对」但点击偏 | 行业 | 采集有时仍像满屏，注入用虚拟化 metrics | Host 一律 early DPI aware（与现 `mux_host` / spike_host 一致并保留） |

### L.2 验收矩阵（DPI / 缩放）

| 场景 | 最低要求 | 记入 |
|------|----------|------|
| Host Win7 @ 100% + Viewer Win11 @ **100%** | 点得准 | RESULTS |
| Host Win7 @ 100% + Viewer Win11 @ **125%** | 点得准、无明显糊到不能用 | RESULTS（**必测**） |
| Host Win7 @ 100% + Viewer Win11 @ **150%** | 点得准 | RESULTS（**必测**） |
| Viewer 窗口缩小 letterbox 后再点四角/中心 | 映射正确 | G3 |
| （若有）Host 或 Viewer 为 Win8+ 且系统缩放 ≠ 100% | 同上 | 有环境则测 |

不要求：每监视器不同 DPI 的多屏拼接、动态改 Host 缩放热切换（若测到记一笔即可）。

### L.3 实现备忘（探针编码时）

1. Viewer 清单示例方向：`dpiAware` / `dpiAwareness=system`（P0 用 system，不上 permonitor 除非做满 L4）。  
2. 启动日志打一行：进程 DPI awareness、监控 DPI、客户区大小、远端帧大小、letterbox scale——便于 Win11 联调。  
3. 与现网 LibVNC 对照时：**两边 Viewer 都应 DPI aware**，避免「对照本身点偏」污染档 B 判断。

## H. 安全与滥用（探针也要有底线）

| # | 坑 | 类型 | 为何危险 | 本探针怎么避 |
|---|----|------|----------|--------------|
| H1 | 口令硬编码且无失败限速 | 行业 | 内网扫端口撞库 | P0 可沿用 PSK；至少失败打日志；不在探针加复杂账号体系，但**不要**去掉 fail-closed |
| H2 | 日志打印口令/完整帧 | 行业 | 泄密与磁盘爆 | 日志只打事件与尺寸，不打 secret、不打像素 |

## J. 本探针「出门前」避坑抽查（精简）

每次 Gate 或每周五，至少确认：

1. **没有**为视频区或整屏 JPEG 改默认策略（A1/A2）  
2. **有** newest-frame-wins 与发送上限，不是无限队列（C1/C2）  
3. **有** Input 优先于 Video 的调度证据（C3/E2）  
4. **开了** `TCP_NODELAY`（E1）  
5. **长度帧**解析正确，畸形 len 可断（E4/E5/E6）  
6. **断连**释放互斥与修饰键（E8/D2）  
7. **结论来自 Win7 Host**，不是只 Win11 双端（G1）  
8. **没**引入 Mirror / 第三方 VNC / Go-Rust 媒体面（A5/A6）  
9. **DPI**：Viewer 非 unaware；协议坐标 = Host 帧像素；**125%/150%** 点击抽测通过（L1/L7/L8）
