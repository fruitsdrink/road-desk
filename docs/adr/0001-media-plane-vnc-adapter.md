# 媒体面采用可替换的 VNC 适配器

Status: accepted

高速公路路段远控需要共享控制台（类 VNC）媒体面，且必须跑在 Win7 x64 / Windows Server 2008 / 2012 上。历史上两版完全自研媒体面均失败：第一版因兼顾桌面内视频观感导致 FPS 长期偏低；第二版在 64×64 分块与整屏 JPEG 路线上反复出现黑屏/闪屏。因此 MVP 不再全量自研媒体面，也不深度 Fork 某 VNC 整包当产品；控制面始终自研，媒体面先以 VNC 系实现并隔离在可替换适配器后，并行做换芯工作量探针，再决定是否收回媒体面实现。

## Considered Options

- **A. 控制面自研 + VNC 媒体面适配器（可替换）** — 采纳为 MVP 策略
- **B. 控制面与媒体面均自研** — 曾两度失败；仅在探针证明换芯成本可接受且必要时再议
- **C. 深度 Fork 现成 VNC 产品整包** — 拒绝；后期旁观、中继、审计、合规替换会与上游缠死

## Consequences

- MVP 体验对齐经典 WinVNC（TightVNC 一档）看屏与键鼠手感；验收以 GUI 操作优先，不以桌面内视频区流畅为准
- 目录、账号、审计、会话互斥/旁观、中继信令等不得长进 RFB/某一 Fork 内部，须落在控制面或自有通道
- 换芯探针应重点覆盖：真实车道桌面采集与注入稳定性、登录前/锁屏远控可行性、文件传输通道是否必须离开 VNC
