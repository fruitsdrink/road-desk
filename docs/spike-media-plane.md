# 媒体面换芯与风险探针计划

Status: planned  
Related: [ADR-0001](./adr/0001-media-plane-vnc-adapter.md), [ADR-0002](./adr/0002-mvp-gpl-then-compliant-media-base.md), [CONTEXT.md](../CONTEXT.md)

## 目的

用有时限、可扔掉的验证，回答：VNC 系媒体面适配器能否支撑 MVP 与关键目标能力；若不能或正式交付必须换芯，工作量与触发条件是什么。

本探针**不替代 MVP 主线**，也不重做历史上已失败的全量自研媒体面。

## 时间盒

建议 **1～2 周**。到期必须产出结论，不因「再调一调帧率」延期。

## 环境

- **被控端**：Win7 x64 车道电脑或同等机电工作站；另备 Windows Server 2008/2012 各至少一台更佳
- **操作端**：Win7 x64
- **对照**：同一被控端上可并排使用的经典 WinVNC（TightVNC 一档）客户端/服务端
- **网络**：路段内网或等价局域网直连（本探针不测中继）

## 成功标准（总原则）

- **GUI 操作优先**：菜单、按钮、对话框可准确查看与操作
- **体验对齐经典 WinVNC 手感**，不对标本地键鼠
- **桌面内视频预览区**：允许卡顿或画质下降，不作为成功条件
- **稳定性**：连续远控不少于 30 分钟，无黑屏、无闪屏、无异常掉线

## 探针项

### P1 — 真实桌面采集与注入（必做）

**问题**：在真实车道/机电桌面上，VNC 系适配器能否达到 MVP 验收级看屏与键鼠？

**做法**：

1. 被控端运行候选 VNC 系服务（可为 GPL，仅内部）
2. 操作端连接后完成一次业务 GUI 操作（开窗口、改一项配置、确认对话框）
3. 与经典 WinVNC 并排对比手感
4. 连续会话 ≥ 30 分钟

**通过**：P1 达到上述成功标准。  
**失败**：黑屏/闪屏/键鼠不可用/明显差于对照 WinVNC → 立即复盘采集后端与适配器选型，暂停堆控制面功能。

### P2 — 桌面内视频区干扰（必做）

**问题**：桌面存在视频预览时，GUI 是否仍可用？（回归第一版失败模式）

**做法**：在含摄像机/视频预览的车道界面上重复 P1 的 GUI 操作；记录视频区是否拖垮整体可操作性。

**通过**：视频区可卡顿，但 GUI 仍可完成操作。  
**失败**：为「看清视频」调参后 GUI 不可用，或默认参数下整个桌面不可用 → 记录为适配器/编码策略风险，MVP 验收文案保持「视频区不保证」，并评估是否需脏矩形/降质策略。

### P3 — 登录前 / 锁屏（目标风险，必做）

**问题**：目标「登录前远控」用现有 VNC 系能否做？代价是什么？

**做法**：

1. 被控端处于锁屏、注销后的登录界面，尝试连接并注入输入
2. 记录是否需要镜像驱动、特殊安装、高权限服务、额外组件
3. **不做 UAC 安全桌面**（除非顺手观察到现象，记一笔即可）

**结论选项**（三选一写进报告）：

- 现有组件可接受地支持登录前/锁屏
- 需驱动或重度定制，目标阶段单列里程碑
- 基本不可行，登录前能力必须换芯或自研采集路径

### P4 — 文件传输通道边界（目标风险，必做）

**问题**：目标必选的文件传输，走 VNC 扩展还是自有通道？与适配器边界是否冲突？

**做法**：

1. 调研候选 VNC 系的文件传输能力与许可
2. 做最小打通或纸面设计：会话建立后传一个小文件往返
3. 评估接到「自有会话 API」后，替换媒体面时文件通道是否必须重写

**结论选项**：

- 可用 VNC 扩展且替换成本可接受
- 应自研文件通道，与画面/键鼠媒体面并列
- 文件传输与 GPL/合规绑定过紧，交付前必须剥离

### P5 — 合规替换工作量（必做，可与 P1 并行估）

**问题**：去掉 GPL 等 copyleft 依赖、换成可正式交付底座，要多少人周？触发条件？

**做法**：列出 MVP 实际链接/调用的媒体面依赖与许可证；给出 1～2 个合规候选（商业 SDK、宽松许可库、或探针后的自研适配器）；粗估替换人周。

**输出**：交付前必须替换的依赖清单 + 粗估人周 + 「可继续用适配器直到交付前」或「应提前换」的建议。

## 明确不做

- 全量自研媒体面（协议 + 采集从零再来一遍）
- 中心目录、管理端账号、审计、中继
- 浏览器操作端
- 以视频区 FPS 为优化目标
- 将探针构建当作正式交付安装包

## 输出物

到期交付一页结论（可附原始笔记），至少包含：

1. **P1/P2 结论**：VNC 适配器是否足以支撑 MVP
2. **P3/P4 结论**：登录前、文件传输各自走「适配器内 / 自有通道 / 必须换芯」
3. **P5 结论**：合规替换粗估与建议时间点
4. **总判**（选一）：
   - **继续 A**：VNC 适配器用于 MVP，目标能力按控制面/自有通道扩展，交付前换合规实现
   - **局部自研**：画面+键鼠保留适配器；登录前和/或文件传输自研通道
   - **调整选型**：P1 失败，更换 VNC 系候选或采集后端后再探针，而不是转向全量自研

## 与主线关系

| 主线（MVP） | 探针 |
|-------------|------|
| 做出可演示的操作端 + 被控端代理 | 回答能否稳、以后换不换得起 |
| 代码可保留 | 代码默认可扔，结论必须保留 |
| 可用 GPL 组件 | 同步算清交付前怎么去掉 |

主线与探针发现冲突时：**以真实被控端上的稳定性为准**，更新 ADR-0001/0002 的 Consequences，而不是放宽「不黑屏/不闪屏」验收。
